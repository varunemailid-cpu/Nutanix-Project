## Response:

tar itself does not support password protection. The usual method is to create the tar archive first, then encrypt it.

For Linux/macOS, a good option is gpg:

tar -czf nkp-offline.tar.gz nkp-offline/
gpg -c nkp-offline.tar.gz

It will prompt you for a password and create:

nkp-offline.tar.gz.gpg

To decrypt later:

gpg -o nkp-offline.tar.gz -d nkp-offline.tar.gz.gpg

Then extract:

tar -xzf nkp-offline.tar.gz

If gpg isn't available, OpenSSL is another option:

tar -czf nkp-offline.tar.gz nkp-offline/
openssl enc -aes-256-cbc -salt -pbkdf2 -in nkp-offline.tar.gz -out nkp-offline.tar.gz.enc

Decrypt:

openssl enc -d -aes-256-cbc -pbkdf2 -in nkp-offline.tar.gz.enc -out nkp-offline.tar.gz

For your air-gapped NKP bundle, I'd use GPG if both your Mac and bastion have it available.

## Response:

The simplest option is a password-protected ZIP.

On macOS or Linux:

zip -er nkp-offline.zip nkp-offline/

It will ask:

Enter password:
Verify password:

To extract:

unzip nkp-offline.zip

It will prompt for the password.

For a single file:

zip -e myfile.zip myfile.tar

If you want stronger encryption, use 7z instead:

7z a -p -mhe=on nkp-offline.7z nkp-offline/

This will prompt for a password. -mhe=on also hides/encrypts the file names inside the archive.

For your NKP offline bundle, I would use:

7z a -p -mhe=on nkp-offline.7z nkp-offline/

if 7z is available; otherwise:

zip -er nkp-offline.zip nkp-offline/
