Professional Harbor Build and ESXi-to-AHV Migration Runbook

Use the following design:

Internet-connected ESXi
┌───────────────────────────────────────────────────────────────┐
│ Ubuntu Server 24.04 LTS                                      │
│ 8 vCPU / 16 GB RAM                                           │
│ Disk 1: 150 GB - OS, Docker engine and Docker image cache    │
│ Disk 2: 150 GB - LVM/ext4 mounted on /data                   │
│ Harbor HTTPS using temporary staging CA                      │
│ Permanent name: harbor01.registry.example.com                │
└───────────────────────────────────────────────────────────────┘
                         │
                         │ Clean shutdown and cold-copy both VMDKs
                         ▼
Air-gapped Nutanix AHV
┌───────────────────────────────────────────────────────────────┐
│ Same VM disks and permanent Harbor FQDN                      │
│ New IP, gateway, DNS and virtual NIC name                    │
│ Enterprise CA-signed server certificate                     │
│ Internal DNS/NTP only                                        │
└───────────────────────────────────────────────────────────────┘

Critical design decisions

Do not use the IP address as the Harbor registry name. Use the final production FQDN from the first installation, such as:

harbor01.registry.example.com

During staging, resolve that name to the ESXi staging IP using /etc/hosts or temporary DNS. After migration, update internal DNS to the AHV production IP. Because the certificate validates the FQDN rather than the IP, an IP change does not require changing image names.

Use the offline Harbor installer even while connected to the internet. The full installer and container images will then remain available inside the dark site.

The second 150 GB disk mounted at /data stores more than repository layers. It also stores Harbor’s database, registry content, secrets, job-service data, scanner data and other persistent state. Harbor explicitly preserves data_volume when containers are removed and recreated. (Harbor)

Use a temporary staging CA only for the internet-connected build. After migration, replace the Harbor server certificate with one signed by the enterprise CA for the same FQDN. Harbor recommends trusted CA certificates for production and requires a SAN-compliant server certificate. (Harbor)

This is a professionally hardened single-node Harbor, but it is not highly available. Failure of this VM, its data disk or the AHV container hosting it will stop the registry.

As of September 11, 2026, Harbor v2.15.2 is the latest published stable release. The official offline installer SHA-256 is included below. (GitHub API) Harbor’s official recommended baseline is 4 CPU, 8 GB RAM and 160 GB disk; I recommend 8 vCPU and 16 GB RAM for this deployment, especially when multiple Kubernetes nodes pull concurrently or Trivy is enabled. (Harbor)

Phase 4 - Create a reusable static network configuration command

The ESXi NIC might be called ens192, while the AHV NIC may become ens3, enp1s0 or another name. This helper allows the address to be changed safely from the hypervisor console.

cat >/usr/local/sbin/configure-static-network <<'SCRIPT'
#!/usr/bin/env bash
set -Eeuo pipefail

if [[ $EUID -ne 0 || $# -ne 6 ]]; then
  echo "Usage:"
  echo "  configure-static-network <interface> <address/prefix> <gateway> <dns1> <dns2> <search-domain>"
  exit 2
fi

IFACE="$1"
ADDRESS="$2"
GATEWAY="$3"
DNS1="$4"
DNS2="$5"
SEARCH_DOMAIN="$6"

ip link show dev "$IFACE" >/dev/null

BACKUP="/root/netplan-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BACKUP"
cp -a /etc/netplan/. "$BACKUP/" 2>/dev/null || true

mkdir -p /etc/cloud/cloud.cfg.d
printf 'network: {config: disabled}\n' \
  >/etc/cloud/cloud.cfg.d/99-disable-network-config.cfg

rm -f /etc/netplan/*.yaml

cat >/etc/netplan/01-harbor-static.yaml <<EOF
network:
  version: 2
  renderer: networkd
  ethernets:
    ${IFACE}:
      dhcp4: false
      dhcp6: false
      addresses:
        - ${ADDRESS}
      routes:
        - to: default
          via: ${GATEWAY}
      nameservers:
        addresses:
          - ${DNS1}
          - ${DNS2}
        search:
          - ${SEARCH_DOMAIN}
EOF

chmod 600 /etc/netplan/01-harbor-static.yaml
netplan generate

echo
echo "Configuration generated successfully."
echo "Run the following from the VM console:"
echo "  netplan try --timeout 120"
SCRIPT

Phase 8 - Generate the temporary staging CA and server certificate

Harbor must receive a server certificate and private key. Clients receive only the CA certificate. Never copy the Harbor server private key to Kubernetes nodes or Docker clients.

Generate the temporary staging root CA:

openssl genpkey \
  -algorithm RSA \
  -pkeyopt rsa_keygen_bits:4096 \
  -out staging-root-ca.key

openssl req \
  -x509 \
  -new \
  -sha256 \
  -days 3650 \
  -key staging-root-ca.key \
  -out staging-root-ca.crt \
  -subj "/C=AE/O=Harbor Staging/OU=Platform/CN=Harbor Staging Root CA"

Generate the Harbor private key and CSR:

openssl genpkey \
  -algorithm RSA \
  -pkeyopt rsa_keygen_bits:4096 \
  -out harbor-staging.key

openssl req \
  -new \
  -sha256 \
  -key harbor-staging.key \
  -out harbor-staging.csr \
  -subj "/C=AE/O=Harbor Staging/OU=Platform/CN=${HARBOR_FQDN}"

Create SAN extensions:

cat >harbor-staging-v3.ext <<EOF
authorityKeyIdentifier=keyid,issuer
basicConstraints=critical,CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=DNS:${HARBOR_FQDN}
EOF

  -out harbor-staging.crt \
  -extfile harbor-staging-v3.ext

Phase 13 - Install the Harbor validation command

Harbor exposes /api/v2.0/health without authentication and reports healthy only when all listed Harbor components are healthy. (GitHub)

cat >/usr/local/sbin/validate-harbor <<'SCRIPT'
#!/usr/bin/env bash
set -Eeuo pipefail

FQDN="${1:?Usage: validate-harbor <fqdn> <ca-file>}"
CA_FILE="${2:?Usage: validate-harbor <fqdn> <ca-file>}"

fail() {
  echo "FAIL: $*" >&2
  exit 1
}

pass() {
  echo "PASS: $*"
}

warn() {
  echo "WARN: $*" >&2
}

[[ -r "$CA_FILE" ]] || fail "CA file cannot be read: $CA_FILE"

RESOLVED_IP="$(
  getent ahostsv4 "$FQDN" |
    awk 'NR == 1 {print $1}'
)"

[[ -n "$RESOLVED_IP" ]] ||
  fail "FQDN does not resolve: $FQDN"

pass "$FQDN resolves to $RESOLVED_IP"

mountpoint -q /data ||
  fail "/data is not mounted"

[[ -f /data/.harbor-data-volume ]] ||
  fail "/data marker file is missing"

pass "/data is mounted and marker exists"

systemctl is-active --quiet docker ||
  fail "Docker service is not active"

pass "Docker service is active"

cd /opt/harbor

MISSING_SERVICES="$(
  comm -23 \
    <(docker compose config --services | sort -u) \
    <(docker compose ps --status running --services | sort -u)
)"

[[ -z "$MISSING_SERVICES" ]] ||
  fail "Harbor services not running: $MISSING_SERVICES"

pass "All Harbor Compose services are running"

HEALTH="$(
  curl \
    --silent \
    --show-error \
    --fail \
    --connect-timeout 10 \
    --max-time 30 \
    --cacert "$CA_FILE" \
    "https://${FQDN}/api/v2.0/health"
)"

echo "$HEALTH" | jq .

echo "$HEALTH" |
  jq -e '.status == "healthy"' >/dev/null ||
  fail "Harbor API reports an unhealthy state"

pass "Harbor health API reports healthy"

REGISTRY_CODE="$(
  curl \
    --silent \
    --show-error \
    --output /dev/null \
    --write-out '%{http_code}' \
    --connect-timeout 10 \
    --max-time 30 \
    --cacert "$CA_FILE" \
    "https://${FQDN}/v2/"
)"

[[ "$REGISTRY_CODE" == "200" || "$REGISTRY_CODE" == "401" ]] ||
  fail "Unexpected registry API response: HTTP $REGISTRY_CODE"

pass "Registry v2 endpoint responded with HTTP $REGISTRY_CODE"

openssl s_client \
  -connect "${FQDN}:443" \
  -servername "$FQDN" \
  -CAfile "$CA_FILE" \
  -verify_return_error \
  </dev/null >/dev/null 2>&1 ||
  fail "TLS chain validation failed"

pass "TLS chain validation succeeded"

TEMP_CERT="$(mktemp)"
trap 'rm -f "$TEMP_CERT"' EXIT

openssl s_client \
  -connect "${FQDN}:443" \
  -servername "$FQDN" \
  -showcerts \
  </dev/null 2>/dev/null |
  openssl x509 -outform PEM >"$TEMP_CERT"

openssl x509 \
  -in "$TEMP_CERT" \
  -noout \
  -checkhost "$FQDN" >/dev/null ||
  fail "Certificate SAN does not match $FQDN"

pass "Certificate SAN matches $FQDN"

if openssl x509 \
    -in "$TEMP_CERT" \
    -noout \
    -checkend 3888000 >/dev/null; then
  pass "Certificate is valid for more than 45 days"
else
  warn "Certificate expires in fewer than 45 days"
fi

DATA_USAGE="$(
  df -P /data |
    awk 'NR == 2 {gsub("%", "", $5); print $5}'
)"

if (( DATA_USAGE >= 85 )); then
  fail "/data utilization is ${DATA_USAGE}%"
elif (( DATA_USAGE >= 75 )); then
  warn "/data utilization is ${DATA_USAGE}%"
else
  pass "/data utilization is ${DATA_USAGE}%"
fi

echo
echo "Harbor validation completed successfully."
SCRIPT

ESXi migration rules

Before copying:

The VM must be fully powered off, not suspended.

Consolidate or remove VMware snapshots.

Copy/export both disks.

For manually copied VMware disks, ensure the VMDK descriptor and its backing extent are both included.

Do not copy only the OS disk.

Preserve the original boot firmware: BIOS-to-BIOS or UEFI-to-UEFI.

Keep the ESXi source VM powered off during AHV validation.

Never run source and target simultaneously with the same FQDN and registry data.

Keep the source VM as the rollback point until AHV acceptance is complete.

An OVA export, approved VMDK import workflow or Nutanix Move is safer than copying datastore files from a running environment.

Phase 27 - Generate the enterprise CA CSR

The enterprise certificate must contain:

Subject CN: harbor01.registry.example.com
SAN: DNS:harbor01.registry.example.com
Extended Key Usage: Server Authentication
Key Usage: Digital Signature, Key Encipherment

Do not request an IP SAN unless clients are genuinely required to connect by IP. FQDN-only access makes future IP changes easier.

Create the production private key:

install -d -m 0700 /root/harbor-production-pki
cd /root/harbor-production-pki
umask 077

openssl genpkey \
  -algorithm RSA \
  -pkeyopt rsa_keygen_bits:4096 \
  -out harbor-production.key

Create the CSR configuration. Replace the subject details with the customer’s approved values:

cat >harbor-production-csr.cnf <<EOF
[req]
prompt = no
distinguished_name = distinguished_name
req_extensions = request_extensions

[distinguished_name]
C = AE
ST = Abu Dhabi
L = Abu Dhabi
O = CUSTOMER-ORGANIZATION
OU = Infrastructure
CN = ${HARBOR_FQDN}

[request_extensions]
basicConstraints = critical,CA:FALSE
keyUsage = critical,digitalSignature,keyEncipherment
extendedKeyUsage = serverAuth
subjectAltName = @subject_alt_names

[subject_alt_names]
DNS.1 = ${HARBOR_FQDN}
EOF

Generate the CSR:

openssl req \
  -new \
  -sha256 \
  -key harbor-production.key \
  -out harbor-production.csr \
  -config harbor-production-csr.cnf

Validate the CSR:

openssl req \
  -in harbor-production.csr \

Phase 29 - Install the enterprise CA-signed certificate

Assume the files have been placed in:

/root/ca-return/harbor-production.crt
/root/ca-return/intermediate-chain.crt
/root/ca-return/enterprise-root-ca.crt

Set variables:

LEAF_CERT="/root/ca-return/harbor-production.crt"
INTERMEDIATE_CHAIN="/root/ca-return/intermediate-chain.crt"
ROOT_CA="/root/ca-return/enterprise-root-ca.crt"

Validate the chain:

openssl verify \
  -CAfile "$ROOT_CA" \
  -untrusted "$INTERMEDIATE_CHAIN" \
  "$LEAF_CERT"

Validate the hostname:

openssl x509 \
  -in "$LEAF_CERT" \
  -noout \
  -checkhost "$HARBOR_FQDN"

Validate that the certificate matches the private key:

CERT_PUBLIC_KEY_HASH="$(
  openssl x509 \
    -in "$LEAF_CERT" \
    -pubkey \
    -noout |
  openssl pkey \
    -pubin \
    -outform DER |
  sha256sum |
  awk '{print $1}'
)"

PRIVATE_KEY_HASH="$(
  openssl pkey \
    -in "$PRODUCTION_KEY" \
    -pubout \
    -outform DER |
  sha256sum |
  awk '{print $1}'
)"

echo "Certificate public key: $CERT_PUBLIC_KEY_HASH"
echo "Private key public key:  $PRIVATE_KEY_HASH"

test "$CERT_PUBLIC_KEY_HASH" = "$PRIVATE_KEY_HASH" || {
  echo "Certificate and private key do not match."
  exit 1
}

Back up the staging certificate:

CERT_BACKUP="/etc/harbor/certs.backup.$(date +%Y%m%d-%H%M%S)"
cp -a /etc/harbor/certs "$CERT_BACKUP"

echo "Certificate backup: $CERT_BACKUP"

Build the server full chain. Do not normally include the root CA in the server chain.

cat \
  "$LEAF_CERT" \
  "$INTERMEDIATE_CHAIN" \
  >/etc/harbor/certs/harbor-fullchain.crt

install -m 0600 \
  "$PRODUCTION_KEY" \
  /etc/harbor/certs/harbor.key

chmod 644 /etc/harbor/certs/harbor-fullchain.crt
chown root:root \
  /etc/harbor/certs/harbor-fullchain.crt \
  /etc/harbor/certs/harbor.key

Install the enterprise root CA in Ubuntu:

install -m 0644 \
  "$ROOT_CA" \
  /usr/local/share/ca-certificates/enterprise-harbor-root-ca.crt

update-ca-certificates

Replace Docker’s staging CA with the enterprise root:

install -d -m 0755 \
  "/etc/docker/certs.d/${HARBOR_FQDN}"

install -m 0644 \
  "$ROOT_CA" \
  "/etc/docker/certs.d/${HARBOR_FQDN}/ca.crt"

Regenerate and start Harbor:

cd /opt/harbor
./prepare
docker compose config --quiet

docker compose down -v

systemctl restart docker

systemctl enable harbor
systemctl start harbor

Before this test, the enterprise root CA must be trusted by the Kubernetes node container runtime through the supported NKP, VKS or upstream Kubernetes configuration method. For managed platforms, avoid manually modifying each node because machine replacement can remove the change.

Phase 36 - Application-consistent backup

A snapshot on the same AHV cluster is not the only backup. Maintain an external backup copy according to the required RPO and RTO.

  --numeric-ids \
  --info=progress2 \
  /data/ \
  "$BACKUP_DIR/data/"

  --xattrs \
